                                                                • Git & GitHub

                                                                Alur kerja Git yang akan dipakai terus-menerus:

                                                                Working Directory → Staging Area (git add) → Repository (git commit) → Remote GitHub (git push)

                                                                A. Konsep Dasar

                                                                1.1 Version Control

                                                                Version Control adalah sistem untuk mencatat, mengelola, dan melacak perubahan pada file dari waktu ke waktu, sehingga kita dapat mengetahui riwayat perubahan dan kembali ke versi sebelumnya jika diperlukan.

                                                                1.2 Git vs GitHub

                                                                • Git → alat version control di komputer lokal.

                                                                • GitHub → platform online untuk menyimpan repository Git dan berkolaborasi (Pull Request, review, Issues).

                                                                Git = alatnya. GitHub = tempat dan layanan kolaborasinya.

                                                                1.3 Istilah penting

                                                                B. Repository Lokal

                                                                2.1 Siapkan identitas Git

                                                                Dijalankan sekali per komputer, sebelum commit pertama.

                                                                1. Buka terminal.

                                                                2. Isi nama dan email (ganti dengan data kamu):

                                                                  1
                                                                  git config --global user.name "Nama Kamu"
                                                                  2
                                                                  git config --global user.email "email@contoh.com"

                                                                3. Cek hasilnya:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git config --global --list

                                                                2.2 Buat repository (git init)

                                                                1. Buat folder baru bernama git-sample, lalu buka folder itu di VSCode (atau editor lain).

                                                                2. Buka terminal di dalam folder tersebut.

                                                                3. Jalankan:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git init

                                                                4. Terminal akan menampilkan pesan seperti:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  Initialized empty Git repository in .../git-sample/.git/

                                                                5. Git membuat folder tersembunyi .git. Itu “otak” repository. Jangan dihapus atau diedit secara manual.

                                                                  Jika folder belum terlihat: aktifkan Hidden items di File Explorer, atau di PowerShell jalankan ls -Force.

                                                                2.3 Cek kondisi repository (git status)

                                                                1. Jalankan:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git status

                                                                  Repository masih kosong: Git menampilkan branch default (master atau main) dan belum ada commit.

                                                                2. Buat file README.md dengan isi:

                                                                  ​x
                                                                  1
                                                                  # Git Sample
                                                                  2
                                                                  

                                                                  3
                                                                  Repository latihan Git & GitHub.

                                                                3. Jalankan git status lagi.

                                                                  README.md muncul sebagai Untracked files: file sudah ada di Working Directory, tetapi belum masuk Staging Area.

                                                                Arti status yang akan sering muncul:

                                                                • Untracked — file baru, belum pernah git add

                                                                • Modified — file yang sudah pernah di-commit, lalu diubah

                                                                • Changes to be committed — sudah git add, siap di-commit

                                                                • working tree clean — tidak ada perubahan yang belum di-commit

                                                                Jalankan git status sebelum setiap git add dan git commit.

                                                                2.4 Masukkan file ke Staging Area (git add)

                                                                1. Tambahkan README.md:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git add README.md

                                                                2. Jalankan git status. File sekarang di Changes to be committed.

                                                                Perintah lain yang sering dipakai nanti:

                                                                xxxxxxxxxx
                                                                3
                                                                1
                                                                git add .              # semua perubahan di folder saat ini
                                                                2
                                                                git add -A             # semua perubahan di seluruh repo, termasuk file yang dihapus
                                                                3
                                                                git restore --staged README.md   # batalkan staging, file tidak terhapus

                                                                2.5 Simpan snapshot (git commit)

                                                                1. Pastikan file sudah di-staging, lalu:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git commit -m "chore: inisialisasi repository dengan README"

                                                                2. Jalankan git status. Seharusnya: nothing to commit, working tree clean.

                                                                3. Ubah file README.md

                                                                4. Jalankan perintah berikut

                                                                  xxxxxxxxxx
                                                                  2
                                                                  1
                                                                  git add README.md
                                                                  2
                                                                  git commit -m "docs: lengkapi deskripsi README"

                                                                2.6 Best practice pesan commit

                                                                Standar industri yang paling luas dipakai adalah Conventional Commits 1.0.0, dengan daftar tipe dari Angular convention / @commitlint/config-conventional. Format ini juga dipakai tool seperti commitlint dan semantic-release untuk changelog dan versi otomatis.

                                                                Pesan commit adalah catatan untuk diri sendiri dan tim. Tujuannya: orang lain (atau kamu di masa depan) paham apa yang berubah dan mengapa, tanpa harus membuka seluruh diff.

                                                                Format

                                                                xxxxxxxxxx
                                                                5
                                                                1
                                                                <tipe>(opsional-scope): ringkasan singkat
                                                                2
                                                                

                                                                3
                                                                penjelasan tambahan jika perlu (body)
                                                                4
                                                                

                                                                5
                                                                footer opsional (misalnya BREAKING CHANGE atau Refs)

                                                                Contoh:

                                                                xxxxxxxxxx
                                                                2
                                                                1
                                                                git commit -m "feat: tambah form login"
                                                                2
                                                                git commit -m "fix(auth): perbaiki validasi email pada form daftar"

                                                                Kalau perlu penjelasan lebih panjang:

                                                                xxxxxxxxxx
                                                                1
                                                                1
                                                                git commit -m "fix: cegah login tanpa password" -m "Validasi sebelumnya hanya cek email. Password kosong tetap lolos ke server."

                                                                Daftar tipe standar industri

                                                                Spek Conventional Commits wajib punya feat dan fix. Tipe lain yang dipakai industri (Angular / commitlint) adalah 11 tipe berikut. Bukan add, edit, update, atau improv — kata itu masuk ke ringkasan, bukan ke tipe.

                                                                Breaking change (ubah API / perilaku lama rusak) ditandai ! atau footer BREAKING CHANGE: — ini MAJOR 1.4.2 → 2.0.0, berlaku untuk tipe apa pun:

                                                                xxxxxxxxxx
                                                                2
                                                                1
                                                                git commit -m "feat(api)!: ubah response login menjadi JWT"
                                                                2
                                                                git commit -m "feat: drop dukungan PHP 7" -m "BREAKING CHANGE: aplikasi sekarang membutuhkan PHP 8.1."

                                                                Kata seperti add / edit / improve bukan tipe

                                                                Scope (opsional) menandai area kode di dalam kurung: feat(auth):, fix(api):, docs(readme):.

                                                                Aturan ringkasan (baris pertama)

                                                                1. Pakai kalimat perintah (imperative): tambah, perbaiki, hapus — bukan menambahkan atau sudah diperbaiki.

                                                                2. Huruf kecil di awal ringkasan, tanpa titik di akhir.

                                                                3. Usahakan maksimal ~50 karakter. Jangan ceritakan seluruh diff di judul.

                                                                4. Satu commit = satu perubahan logis. Jangan campur fitur, bugfix, dan format dalam satu commit.

                                                                5. Tulis mengapa, bukan hanya nama file. update index.html tidak membantu.

                                                                Contoh yang dihindari vs yang disarankan:

                                                                Untuk Pull Request di GitHub, judul PR mengikuti pola yang sama. Isi deskripsi PR dengan: apa yang diubah, mengapa, dan cara menguji.

                                                                Mulai sekarang, setiap git commit di panduan ini memakai format tipe: ringkasan. Biasakan 11 tipe di atas di tugas dan proyek tim.

                                                                C. History & Inspection

                                                                Fokus: melihat dan memahami perubahan kode.

                                                                3.1 Daftar commit (git log)

                                                                xxxxxxxxxx
                                                                3
                                                                1
                                                                git log
                                                                2
                                                                git log --oneline
                                                                3
                                                                git log --oneline --graph --all

                                                                • git log — lengkap (hash, author, tanggal, pesan)

                                                                • --oneline — satu baris per commit

                                                                • --graph --all — visualisasi branch

                                                                Tekan q untuk keluar dari tampilan log.

                                                                3.2 Perbedaan isi file (git diff)

                                                                1. Ubah README.md lagi, jangan di-commit dulu.

                                                                2. Bandingkan:

                                                                  xxxxxxxxxx
                                                                  3
                                                                  1
                                                                  git diff              # Working Directory vs Staging Area
                                                                  2
                                                                  git diff --staged     # Staging Area vs commit terakhir
                                                                  3
                                                                  git diff HEAD         # Working Directory vs commit terakhir

                                                                3. Kembalikan file ke versi commit terakhir (latihan ini sengaja dibuang):

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git restore README.md

                                                                3.3 Detail satu commit (git show)

                                                                xxxxxxxxxx
                                                                2
                                                                1
                                                                git show
                                                                2
                                                                git show HEAD

                                                                Tanpa argumen, git show menampilkan commit terbaru.

                                                                HEAD = commit yang sedang aktif. HEAD~1 = satu commit sebelumnya.

                                                                D. Branching

                                                                Fokus: mengembangkan fitur tanpa mengganggu kode utama.

                                                                4.1 Konsep branch

                                                                Branch dipakai agar fitur baru tidak mengganggu kode utama (main / master).

                                                                Konvensi sederhana:

                                                                • main — kode yang sudah disepakati

                                                                • fitur-nama — satu branch per fitur

                                                                • fix-nama — satu branch per perbaikan bug

                                                                4.2 Membuat dan berpindah branch

                                                                1. Cek branch saat ini:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git branch

                                                                  Branch aktif ditandai *. Jika masih master, ganti nama ke main:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git branch -M main

                                                                2. Buat branch fitur dan pindah ke sana:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git switch -c fitur-hello

                                                                  Setara dengan perintah lama: git checkout -b fitur-hello. Utamakan git switch.

                                                                3. Ubah README.md, lalu commit di branch ini:

                                                                  xxxxxxxxxx
                                                                  2
                                                                  1
                                                                  git add README.md
                                                                  2
                                                                  git commit -m "feat: tambah bagian hello"

                                                                4. Kembali ke main:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git switch main

                                                                  Isi README.md kembali ke versi main, karena commit hello hanya ada di fitur-hello.

                                                                E. Merge & Conflict

                                                                Fokus: menggabungkan pekerjaan.

                                                                5.1 Gabungkan branch (git merge)

                                                                1. Pastikan berada di branch tujuan (kode utama):

                                                                  xxxxxxxxxx
                                                                  2
                                                                  1
                                                                  git switch main
                                                                  2
                                                                  git merge fitur-hello

                                                                2. Cek hasilnya:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git log --oneline --graph --all

                                                                3. Setelah merge berhasil, hapus branch fitur yang sudah tidak dipakai:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git branch -d fitur-hello

                                                                5.2 Jenis merge

                                                                • Fast-forward — main tidak punya commit baru sejak branch fitur dibuat. Git hanya memajukan pointer main. History tetap lurus.

                                                                • Merge commit — kedua branch punya commit baru. Git membuat commit penggabung.

                                                                5.3 Selesaikan merge conflict

                                                                Conflict muncul jika file yang sama diubah di dua branch pada baris yang tumpang tindih.

                                                                1. Buat dua branch dari main:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git switch -c branch-a

                                                                  Ubah baris yang sama di README.md, lalu commit.

                                                                  xxxxxxxxxx
                                                                  2
                                                                  1
                                                                  git switch main
                                                                  2
                                                                  git switch -c branch-b

                                                                  Ubah baris yang sama dengan isi berbeda, lalu commit.

                                                                2. Gabungkan keduanya:

                                                                  xxxxxxxxxx
                                                                  3
                                                                  1
                                                                  git switch main
                                                                  2
                                                                  git merge branch-a
                                                                  3
                                                                  git merge branch-b

                                                                  Merge kedua biasanya menghasilkan conflict.

                                                                3. Buka file. Cari penanda seperti ini:

                                                                  xxxxxxxxxx
                                                                  5
                                                                  1
                                                                  <<<<<<< HEAD
                                                                  2
                                                                  isi dari branch saat ini
                                                                  3
                                                                  =======
                                                                  4
                                                                  isi dari branch yang di-merge
                                                                  5
                                                                  >>>>>>> branch-b

                                                                4. Pilih isi yang benar (atau gabungkan), hapus ketiga penanda itu, lalu:

                                                                  xxxxxxxxxx
                                                                  2
                                                                  1
                                                                  git add README.md
                                                                  2
                                                                  git commit -m "merge: selesaikan conflict README"

                                                                5. Jika ingin membatalkan merge yang belum selesai:

                                                                  xxxxxxxxxx
                                                                  1
                                                                  1
                                                                  git merge --abort

                                                                Conflict bukan error Git. Artinya dua perubahan perlu keputusan manusia.

                                                                F. Remote Repository

                                                                Fokus: menghubungkan repository lokal dengan server.

                                                                6.1 Buat repository di GitHub

                                                                1. Login ke https://github.com.

                                                                2. Klik New repository.

                                                                3. Isi nama, misalnya git-sample.

                                                                4. Pilih Public atau Private.

                                                                5. Jangan centang “Add a README” — folder lokal sudah punya Git, supaya history tidak bentrok.

                                                                6. Buat repository, lalu salin URL-nya.

                                                                6.2 Sambungkan lokal ke GitHub (git remote dan git push)

                                                                Ganti URL dengan milik kamu:

                                                                xxxxxxxxxx
                                                                3
                                                                1
                                                                git remote add origin https://github.com/username/git-sample.git
                                                                2
                                                                git remote -v
                                                                3
                                                                git push -u origin main

                                                                -u cukup sekali. Setelah itu cukup git push dan git pull.

                                                                HTTPS memakai username + Personal Access Token. SSH memakai kunci yang sudah didaftarkan di GitHub:

                                                                xxxxxxxxxx
                                                                2
                                                                1
                                                                HTTPS: https://github.com/username/git-sample.git
                                                                2
                                                                SSH:   git@github.com:username/git-sample.git

                                                                6.3 git clone, git fetch, dan git pull

                                                                • git clone — menyalin repo yang sudah ada di GitHub ke komputer (termasuk remote origin).

                                                                • git fetch — ambil data remote tanpa mengubah file lokal.

                                                                • git pull — fetch + terapkan perubahan ke branch aktif.

                                                                xxxxxxxxxx
                                                                3
                                                                1
                                                                git clone https://github.com/username/git-sample.git
                                                                2
                                                                git fetch origin
                                                                3
                                                                git pull origin main

                                                                fetch untuk melihat dulu. pull untuk langsung menerapkan.

                                                                G. Kolaborasi GitHub

                                                                Fokus: bekerja dalam tim.

                                                                Alur standar:

                                                                Branch → Commit → Push → Pull Request → Review → Approve → Merge

                                                                7.1 Push branch dan buat Pull Request

                                                                1. Buat branch baru, ubah file, commit.

                                                                  xxxxxxxxxx
                                                                  6
                                                                  1
                                                                  git switch main
                                                                  2
                                                                  git pull
                                                                  3
                                                                  git switch -c fitur-kontak
                                                                  4
                                                                  git add .
                                                                  5
                                                                  git commit -m "feat: tambah info kontak"
                                                                  6
                                                                  git push -u origin fitur-kontak

                                                                2. Di GitHub: buka repository → Compare & pull request.

                                                                3. Isi judul dan deskripsi, lalu buat PR.

                                                                7.2 Review, approve, dan merge

                                                                1. Reviewer membaca perubahan dan bisa berkomentar.

                                                                2. Setelah disetujui (Approve), merge PR ke main.

                                                                3. Di lokal, rapikan:

                                                                  xxxxxxxxxx
                                                                  3
                                                                  1
                                                                  git switch main
                                                                  2
                                                                  git pull
                                                                  3
                                                                  git branch -d fitur-kontak

                                                                  Di GitHub, hapus branch fitur (tombol Delete branch).

                                                                7.3 Kerja tim sehari-hari

                                                                1. Satu orang membuat repo, lalu menambahkan anggota: Settings → Collaborators.

                                                                2. Anggota lain: git clone repository.

                                                                3. Setiap fitur = satu branch. Jangan commit langsung ke main jika tim memakai Pull Request.

                                                                4. Selalu git pull di main sebelum membuat branch baru.

                                                                5. Issues dipakai untuk mencatat bug atau tugas.

                                                                6. Fork dipakai jika tidak punya izin write pada repo orang lain: fork → clone fork sendiri → branch → PR ke repo asli.

                                                                H. Undo & Perintah Lanjutan

                                                                8.1 Perbaiki kesalahan (undo)

                                                                Contoh:

                                                                xxxxxxxxxx
                                                                5
                                                                1
                                                                git restore README.md
                                                                2
                                                                git restore --staged README.md
                                                                3
                                                                git reset --soft HEAD~1
                                                                4
                                                                git reset --mixed HEAD~1
                                                                5
                                                                git revert HEAD

                                                                git reset --hard HEAD~1 membuang perubahan. Jangan dipakai pada commit yang sudah di-push bersama tim.

                                                                8.2 Perintah lanjutan (opsional)

                                                                Bagian ini tidak wajib untuk praktikum awal. Pakai saat mulai merapikan history.

                                                                Stash — simpan perubahan sementara agar bisa pindah branch:

                                                                xxxxxxxxxx
                                                                3
                                                                1
                                                                git stash push -m "wip: form login"
                                                                2
                                                                git stash list
                                                                3
                                                                git stash pop

                                                                Rebase — letakkan commit kita di atas main agar history linear. Jangan rebase commit yang sudah di-push dan dipakai orang lain:

                                                                xxxxxxxxxx
                                                                2
                                                                1
                                                                git switch fitur-kontak
                                                                2
                                                                git rebase main

                                                                Squash — gabungkan beberapa commit menjadi satu, biasanya lewat git rebase -i HEAD~3.

                                                                Cherry-pick — salin satu commit ke branch aktif: git cherry-pick abc1234

                                                                Tag / release:

                                                                xxxxxxxxxx
                                                                2
                                                                1
                                                                git tag -a v1.0.0 -m "Rilis pertama"
                                                                2
                                                                git push origin v1.0.0

                                                                main → branch baru → ubah → add → commit → push → Pull Request → review → merge
